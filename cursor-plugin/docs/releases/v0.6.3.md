# Cursor plugin 0.6.3

## Plugin fixes

- Native shell/read/grep refusals recommend only a compatible tool actually declared by the client. The gateway still never executes those operations.
- Native refusals mark the run as having responded to an interaction, preventing the plugin's checkpoint fallback from replaying that run.
- Preserve typed HTTP/Connect authentication and quota failures; 401/403/429 cannot be mistaken for a rejected checkpoint even if the response body says `invalid_argument`.
- Preserve Connect cancellation and deadline causes for request-scoped error classification.
- Add bounded recent-event diagnostics without prompts, arguments, results, credentials or event IDs.
- Build usage-estimation input once per execution with a pre-sized buffer, avoiding repeated large-context copies. Content order and token-estimation semantics are unchanged.

## Host and client boundary

The native ABI remains version 1. Error strings remain backward compatible;
optional structured error details are additive. Official CLIProxyAPI releases
that discard these details at the native JSON bridge do not gain request-scoped
cooldown or exposure-aware host replay prevention merely by updating this plugin.
See [stream failure boundaries](https://github.com/yobo2u/omsub/blob/v0.6.3/cursor-plugin/docs/cursor-stream-failures.md).

This version does not modify OpenCode, account/model policy, timeout durations,
or other providers. Client-issued retries and the original private long-context
stall are not claimed fixed. Publishing source, deploying an artifact, and
creating a GitHub release are separate operations.

## Verification

All six plugin packages passed Go 1.25.14 race/shuffle tests and vet; changed Go
files had no LSP errors. The Linux amd64 c-shared build was loaded by official
CLIProxyAPI v7.3.17. Isolated and production checks each observed one canonical
Cursor account, nonempty SSE output with nonzero estimated usage, one synthetic
echo tool call followed by an `OK` result turn with no repeated tool call, and a
400 response for empty messages. Manager v1.14.0 was also checked after upgrade.

These checks did not replay the original private long-context incident. Native
JSON bridge error flags in this plugin are not proof of host-side cooldown/retry fixes.
The performance benchmark measures allocation for constructing usage text, not
end-to-end inference speed or a guarantee against upstream stalls.

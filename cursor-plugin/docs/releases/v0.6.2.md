Cursor plugin v0.6.2 fixes account identity duplication and unanswered MCP catalog queries. The native plugin ABI remains unchanged.

## Fixes

- Let the host derive parsed account IDs from the physical auth-file path. New OAuth accounts use a consistent `.json` filename/ID, while refresh leaves identity fields unset so the host retains the existing account identity. This prevents a model-settings save and the file watcher from registering the same credential under different IDs.
- Answer Cursor `mcp_state_exec_args` (field 36) with the current request's registered function definitions and schemas. Previously, the embedded descriptor did not recognize this request and the server waited until the no-progress timeout before any client tool call was emitted.
- Limit catalog answers to the requested provider and the tools supplied in that request. A catalog lookup or `kick_only` request does not start a service, connect to another provider, read gateway files, or execute a tool.
- Return typed refusals/errors for unsupported native Web/Exa search, fetch, mode switch, questions and plan creation. VM setup fails explicitly instead of fabricating success. Preserve existing image approval and native grep/read/shell refusal behavior.
- Prevent fresh checkpoint replay after an interaction response has been attempted. Add bounded, value-free interaction-query diagnostics to progress-timeout errors; query contents, credentials and correlation IDs are excluded.
- Compare image-approval test responses by protobuf message content instead of unstable serialization order.

## Compatibility and upgrade

- No token rotation, credential-file rename, account-policy change, model-policy change or saved OpenCode conversation migration is required. Restart the host when installing the new binary to rebuild in-memory account registrations.
- The 90-second meaningful-progress timeout is unchanged. Heartbeats are not treated as progress, and this release does not add automatic tool execution or retries.
- This fix covers the identified MCP catalog stall, not every possible Cursor timeout, HTTP 499, repeated operation, upstream failure, or host-level credential failover.
- Packages are `cursor_0.6.2_linux_amd64.zip` (store) and `cursor-plugin-0.6.2-linux-amd64.tar.gz` (manual installer). Source commits and local builds do not publish a GitHub Release or upgrade a running service.

## Protocol provenance and validation

The original `agent.desc` is unchanged. The additive `mcp_state.textproto` contract records the MCP state fields needed for interoperability, cross-checked against installed Cursor 3.21.18 and an isolated synthetic request to the live Cursor endpoint. No proprietary application source is included.

Regression coverage includes account parse/login/refresh identity, interaction refusal and replay boundaries, MCP provider filtering, exact tool schema round-trip, empty catalogs, and a real HTTP/2 transport that withholds tool handoff until it receives the correlated catalog answer. Synthetic acceptance is not proof that every private OpenCode session is fixed; retest the original session after an actual deployment.

For this release candidate, the full six-package Go race/shuffle suite, vet, Go LSP checks and Linux amd64 Go 1.25.14 shared-library build passed. An isolated CLIProxyAPI v7.3.15 container loaded the candidate and completed a real Cursor SSE echo roundtrip: one tool call, then `OK` with no further tool calls, nonzero usage and `[DONE]` on both turns. Empty-message input returned HTTP 400. The container showed one canonical Cursor account; production was not restarted or upgraded by this validation. `gofumpt`, `golangci-lint` and `nilaway` were unavailable; only gofmt, vet, LSP and runtime/test checks are claimed.

This is an unofficial community plugin for user-authorized Cursor accounts. Review `DISCLAIMER.md` before installation.

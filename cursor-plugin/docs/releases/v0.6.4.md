# Cursor plugin 0.6.4

## Image-write collision fix

- Repeated native image writes with the same requested path and image bytes reuse the run's successful write, while preserving each reply's correlation IDs.
- Concurrent requests, existing files and different images using the same basename receive separately owned, exclusively created filenames. The actual path is returned to Cursor; existing files are never overwritten or deleted.
- Preserve the stable project folder, direct-child path restriction, assets-directory symlink rejection, image MIME check and 16 MiB per-image limit.
- Cleanup removes only files created by the current run and clears its write cache. Image output remains inline `message.images` / `delta.images`.

## Scope

This release addresses the shared `create Cursor generated image ...: file exists`
failure across reasoning models. It does not change CPA/Manager versions,
credentials, account policy, clients, other providers, timeout policy or host
retry behavior. Clients must still support the image response extension to
display generated images. This is not a claim that all upstream Cursor errors
or client image-rendering issues are fixed.

## Verification

All six plugin packages passed Go 1.25.14 race/shuffle tests and vet. The original
collision scenarios failed before the fix and passed afterward, including ten
repeated race/shuffle runs. Changed Go files had no LSP errors. A protocol-level
Client.Run test verified image delivery and foreign-file preservation after a
collision.

Official CLIProxyAPI v7.3.17 loaded the Linux amd64 plugin in isolation. With
eight preexisting image filenames, real Grok and Claude image requests completed;
a read-only filesystem watcher observed two remapped file creations and two
matching deletions. The preexisting files were unchanged.

After backing up the previous plugin and restarting only CPA, production checks
on 2026-09-25 passed for `cursor/grok-4.7-xhigh-fast` and
`cursor/claude-fable-5-1-thinking-xhigh`: each returned one JPEG image over HTTP
200/SSE with DONE, no API errors and nonzero estimated usage. Plain text, one
synthetic echo tool call followed by a result turn without another call, and
invalid-input HTTP 400 also passed. One Cursor account and eleven other accounts,
credentials, configuration, other plugins and other container start times were
preserved. No client UI image-rendering acceptance is claimed.

Production acceptance preceded the release commits. Source, built artifact,
deployment and GitHub publication are tracked separately; compiler and VCS
metadata can make candidate and CI binaries differ despite identical Go source.
